Подготовка проекта локально
Убедитесь, что проект собирается локально:
mvn -U -DskipTests clean package
После этого у вас должен появиться исполняемый jar (обычно target/<artifactId>-<version>.jar). Если ваш бот — обычное консольное приложение с public static void main, то достаточно обычного jar;
Пример для maven-shade (в pom.xml добавьте плагин maven-shade и укажите Main-Class).
в Amvera вы указываете путь к jar, который они будут запускать. 
Подготовьте код так, чтобы токен бота брался из переменной окружения
В корне репозитория создайте файл amvera.yml (или amvera.yaml).
Пример:
meta:
  environment: jvm
  toolchain:
    name: maven
    version: 17   # укажите нужную версию JDK (например 17)

run:
  jarName: target/mybot-1.0.jar   # путь к jar относительно корня репозитория
meta.toolchain.version задаёт JDK, который будет использован для сборки (например 11, 17). 
run.jarName — команда, которую Amvera выполнит: java -jar ${run.jarName}. Укажите точный путь до jar, который создаёт Maven.

Создайте репозиторий (Git) для проекта, если ещё нет:

git init
git add .
git commit -m "Initial deploy to Amvera"


В панели Amvera при создании проекта сервис даст вам URL для Git (или вы создаёте проект и привязываете репозиторий). Добавьте remote, например:

git remote add amvera <git-ssh-or-http-url-от-Amvera>


Запушьте код в ветку, указанную Amvera (обычно master/main):

git push amvera master


После push в панели Amvera вы увидите логи сборки и запуска
Войдите в панель управления Amvera → откройте ваш проект → раздел Конфигурация / Переменные и секреты. Там создайте переменную, например:

TELEGRAM_BOT_TOKEN = <ваш_токен_из_BotFather>


Amvera поддерживает разделение обычных переменных и секретов; 
секреты не показываются в логах. После добавления переменной перезапустите контейнер. 
Важно: переменные окружения не доступны в фазе сборки — доступны только при запуске контейнера.
Также в конфигурации необходимо прописать -DskipTests для игнорирования тестов (если вы заранее их не убрали из финальной версии)
